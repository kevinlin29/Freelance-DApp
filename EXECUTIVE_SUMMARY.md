# Executive Summary — Freelance Marketplace DApp

**Project type:** Programming project, Option A (non-tutorial) • **Stack:** Solidity 0.8.20 + Truffle 5.x + Ganache 7.x + Python 3.10+ / Flask 3.x / web3.py 6.x + HTML/CSS/JS (no framework) + web3.js 1.x + MetaMask • **Seed DApp:** built from scratch; no seed source was used, so no third-party attribution is required. The six "major modifications" below are framed as six major features delivered beyond a minimal escrow skeleton.

## What the DApp is
A fully decentralized freelance marketplace on Ethereum in which employers post jobs with milestone-based escrow, freelancers bid on those jobs, and ETH is released milestone-by-milestone as work is completed. The system is **non-custodial**: the Flask backend never holds private keys and never signs transactions — every state-changing call is signed by the user's own wallet in MetaMask. The smart contract is the single source of truth; Flask is a read, index, and config layer only.

## What it does
A job starts when the employer calls `postJob`, depositing the exact sum of milestone amounts into the contract (`require(msg.value == sum(milestoneAmounts))`). Freelancers call `submitBid` with a proposed amount, a proposal string, and an expiry duration. The employer accepts one bid; the job transitions `Open → InProgress` and the accepted freelancer address is locked in. The freelancer then calls `markMilestoneComplete` per milestone; the employer verifies and calls `releaseMilestonePayment`, which transfers that milestone's ETH to the freelancer under a Checks-Effects-Interactions pattern guarded by OpenZeppelin `ReentrancyGuard`. When all milestones are paid, the job auto-transitions to `Completed`, `totalJobsCompleted` increments on the freelancer's profile, and the employer can submit a one-time on-chain rating (1–5) that feeds a cumulative `reputationScore`. If the parties disagree, either can call `raiseDispute`, which freezes all payment release. A separate `MultiSigArbitration` contract runs a 2-of-3 vote among three arbitrators; when two agree on a winner, funds are released via `resolveDispute`. If no consensus is reached within 7 days, `claimTimeout` splits the remaining escrow 50/50 (with odd-wei remainder going to the freelancer) via `resolveDisputeWithSplit`. The contract is pausable by the owner for emergency freeze.

## Why it is relevant
Centralized freelance platforms (Upwork, Fiverr) extract 10–20% fees, hold funds in custodial accounts, control dispute resolution unilaterally, and own reputation data that workers cannot port off-platform. This DApp removes the middleman: escrow is enforced in code, dispute resolution is transparent 2-of-3 multisig with a deterministic timeout fallback, and reputation lives on-chain tied to a wallet address — portable, tamper-proof, and auditable by anyone. The milestone model specifically reduces counter-party risk for both sides: the employer never pre-pays more than one deliverable at a time, and the freelancer has cryptographic proof the funds are already escrowed before starting work.

## The 6 Major Features (each touches both Solidity and the frontend/backend)
1. **Multi-milestone escrow.** Solidity: `Milestone` struct with a `jobId` ownership field, per-milestone `completed`/`paid` flags, `releaseMilestonePayment` + `releaseAllPayments` under CEI + `nonReentrant`, invariant `msg.value == sum(milestoneAmounts)` enforced in `postJob`, auto-transition to `Completed` when the last milestone is paid. Frontend: dynamic milestone rows on the post-job form (`post_job.html` + `employer.js`), per-milestone progress tracker and release button on the job detail page (`job_detail.html`), BigInt wei math to prevent float precision errors.
2. **Bid expiry system.** Solidity: `expiresAt` field on `Bid`, expiry enforcement in `acceptBid` (`block.timestamp < bid.expiresAt`), `withdrawExpiredBid` callable by the freelancer after expiry with `BidWithdrawn` event. Frontend: `bidDuration` input in the bid form (`freelancer.js`), countdown display on bid cards, accept button disabled once expired.
3. **2-of-3 multisig dispute resolution with 7-day timeout.** Solidity: separate `MultiSigArbitration.sol` contract, `submitVote` with vote tally, internal `_executeResolution` when two arbitrators agree, `claimTimeout` after `TIMEOUT_PERIOD = 7 days` splitting funds deterministically 50/50 via `resolveDisputeWithSplit`, `replaceArbitrator` for arbitrator rotation. The main contract gates `resolveDispute` and `resolveDisputeWithSplit` so only the arbitration contract address can call them. Frontend: `arbitrator.html` dashboard showing open disputes with vote buttons, `raiseDispute` button on the job detail page, Flask endpoint `/api/disputes` for the arbitrator view.
4. **On-chain reputation and ratings.** Solidity: `rateFreelancer(jobId, score)` with a one-time-per-job gate (`jobRated` mapping), score range 1–5, cumulative `reputationScore` + `ratingCount` on `Profile`, `totalJobsCompleted` auto-incremented on job completion. Frontend: star rating widget on completed job pages, average rating (`reputationScore / ratingCount`) displayed on freelancer profile cards and next to bids.
5. **User profiles.** Solidity: `Profile` struct with `name`, `bio`, on-chain counters, `createProfile` that also handles updates, `ProfileCreated`/`ProfileUpdated` events. Frontend: profile creation form in both employer and freelancer dashboards (`dashboard_employer.html`, `dashboard_freelancer.html`), Flask route `/api/profile/<address>` for profile lookups, profile display on job detail and bid lists.
6. **Category-based job board with filter and search.** Solidity: `category` field on `Job`, indexed in the `JobPosted` event for efficient backend filtering. Backend: Flask event indexer walks historical `JobPosted`/`JobStatusChanged` events from a persisted block cursor, exposes `/api/jobs` and `/api/jobs/category/<cat>`. Frontend: category filter bar and client-side keyword search on the homepage job board (`index.html`).

## Security, invariants, and verification
The contract enforces CEI ordering on every payment path, uses OpenZeppelin `ReentrancyGuard` on `cancelJob`, `releaseMilestonePayment`, `releaseAllPayments`, `resolveDispute`, `resolveDisputeWithSplit`, and `claimTimeout`, and is `Pausable` by the owner for emergency freeze. A **76-test pytest suite** (escrow invariants, authorization negative tests, dispute edge cases, event correctness, job state machine, milestone edge cases, bid edge cases, cancel/refund, postJob validation, pause/unpause, direct-resolve guards, rating edge cases, consensus guards, and timeout handling) passes against a freshly deployed contract on Ganache, verifying among other things that `postJob` rejects mismatched deposits, that the contract balance returns to zero after full payout, that non-employers cannot release payment, that a single arbitrator vote does not resolve a dispute, that the 7-day timeout splits funds exactly and handles odd-wei remainders, and that every status transition emits a `JobStatusChanged` event for the Flask indexer. The frontend uses `BigInt` for all wei arithmetic; the backend uses `Web3.to_checksum_address` everywhere and a durable indexing cursor keyed by `(txHash, logIndex)` for idempotent event replay.
